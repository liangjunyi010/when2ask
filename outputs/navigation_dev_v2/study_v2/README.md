# Navigation Dev v2 — actual API and physical pilot

ONE physical map group, ONE seeded target for full 2x2 cost factorial; not independent layouts.

48 gate-only ablation cases; 12 end-to-end model episodes; 172/200 authenticated requests. Threshold fixed at 0.5. Gate-only calls are not complete robot episodes.

Technical incident: the first run registered 12 launches, all aborted before any robot action after a DeepSeek JSON-mode HTTP 400. Its 54 requests (48 successful ablations plus six launch-stage attempts) remain counted and its raw files unchanged. Only the JSON format marker was fixed; gates/cost rules were not tuned. The 48 gate cases are reused. This amended run allows 12 valid navigation launches, so combined registrations can reach 24 while completed physical episodes remain capped at 12. Total requests remain capped at 200.

Operational seconds = simulated physical motion + actual answer waiting + 5s × requested slots. API latency and backend tokens stay separate. Actual physics is paced at 1× for online episodes.

## Scope and reproducibility

The full cost-factorial reuses a single target selected by seed before API calls, isolating cost effects. There is one map group, so no independent-group confidence interval, significance, held-out Test, or general navigation claim. All frozen/v1 records are unchanged. Raw requests/responses, failures, models and usage are under ablation/ and episodes/. Plan and source/data hashes are in plan.json.
